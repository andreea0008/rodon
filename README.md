    Фаза 0 — Розблокувати заздалегідь (робити негайно, паралельно з усім)
Apple Developer акаунт ($99/рік).
Запит на Network Extension entitlement (com.apple.developer.networking.networkextension) — схвалення Apple може зайняти тижні, тому подати якнайраніше. Блокер для VPN на iOS.
Фаза 1 — Інфраструктура збірки
CMake під усі платформи: qt_add_executable + qt_add_qml_module, платформенна специфіка в if(IOS)/if(ANDROID).
iOS: окремий target для Network Extension (окремий bundle ID + entitlements), основний застосунок + extension в одній збірці.
Фаза 2 — Архітектурні рішення (закласти поки UI/бек малі — дорого ретрофітити)
RTL/арабська: LayoutMirroring.enabled + childrenInherit: true на корені; усі рядки через qsTr(); логічні краї замість хардкоду anchors.left; дзеркалення іконок-стрілок.
DNS через власну ноду з самого початку (навіть без фільтрації) — щоб потім увімкнути фільтр без зміни клієнта.
Ноди вміють форвардити одна в одну — фундамент для майбутнього multi-hop без переробки.
Фаза 3 — Реєстрація та device binding
Стабільний device ID: iOS identifierForVendor або UUID у Keychain; Android — UUID у захищеному сховищі.
Бек: таблиця devices(user_id, device_id, created_at) з унікальним обмеженням.
Політика «один пристрій»: продумати відв'язку/ліміт (зміна телефона не має блокувати користувача назавжди).
Фаза 4 — Стабільний single-hop VPN (ядро продукту)
Робочий тунель (WireGuard).
Підписки (місячна/річна, StoreKit + валідація на беку).
Вибір ноди.
DNS у тунелі йде на власну ноду.
Фаза 5 — Multi-hop
Архітектуру закладено у Фазі 2/4; вмикати як фічу після стабільного single-hop.
Поверх WireGuard нетривіально (stateless) — вкладені тунелі / маршрутизація на вході.
Фаза 6 — DNS-фільтрація (ads / gambling)
Власний резолвер на hickory-dns.
Blocklists (Hagezi: ads + gambling), оновлення через ArcSwap.
Per-user профілі з PostgreSQL, мапінг tunnel-IP → user.
Блокування публічних DoH-серверів, щоб фільтр не обходився.
Статус «дослідити» — не для першого релізу.
